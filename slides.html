1 · O problema

O que é colorir um grafo?

  • Dado um grafo G = (V, E)
  • Pintar cada vértice com uma cor
  • Vértices vizinhos não podem ter a mesma cor
  • Objetivo: usar o menor número de cores

Esse mínimo é o número cromático χ(G).

myciel3: 11 vértices, 20 arestas, χ = 4

1 · O problema

Por que é importante — e difícil?

Aplicações

  • Horário de provas sem choque
  • Registradores em compiladores
  • Frequências de rádio / antenas
  • Sudoku (coloração com 9 cores)

Complexidade

  • “Dá pra colorir com k cores?” é NP-completo para k ≥ 3 (Karp, 1972)
  • Minimizar cores é NP-difícil
  • A relaxação linear não é inteira
2 · Modelo matemático

Formulação de PLI

min  Σc yc nº de cores usadas
Σc xvc = 1   ∀ v ∈ V (1) uma cor por vértice
xuc + xvc ≤ yc   ∀ (u,v) ∈ E, ∀ c (2) vizinhos ≠
yc ≥ yc+1   ∀ c (3) quebra de simetria
xvc, yc ∈ {0, 1}
  • xvc = 1 se o vértice v recebe a cor c
  • yc = 1 se a cor c é usada
  • K = cores disponíveis, obtido pela heurística DSATUR
  • Tamanho: |V|·K + K variáveis e |E|·K restrições de conflito
2 · Código

Modelo em Python (PuLP + HiGHS)

# variáveis binárias
x = prob.add_variable_dicts("x", (V, C), cat="Binary")
y = prob.add_variable_dicts("y", C, cat="Binary")
# objetivo: minimizar o nº de cores
prob += lpSum(y[c] for c in C)
# (1) cada vértice recebe uma cor
for v in V:
    prob += lpSum(x[v][c] for c in C) == 1
# (2) vizinhos não compartilham cor
for (u, v) in arestas:
    for c in C:
        prob += x[u][c] + x[v][c] <= y[c]
# (3) quebra de simetria
for c in range(K - 1):
    prob += y[c] >= y[c + 1]
# resolve com branch-and-bound (limite de 300 s)
prob.solve(pulp.HiGHS(timeLimit=300))

3 · Análise

Por que a difícil não fecha?

2 vs 6
relaxação linear  vs  ótimo (myciel5)

Com xvc fracionário, cada aresta “divide” as cores e o limite inferior fica em 2.

  • Relaxação fraca: o limite inferior começa muito longe do ótimo
  • Simetria: trocar cores gera soluções iguais (6! = 720)
  • Mycielski não tem triângulos → sem cliques grandes para ajudar a prova
  • Achar a solução é rápido; provar o ótimo é caro
Conclusão

Resumindo

  • Coloração de Grafos é NP-difícil e modelável como PLI com variáveis binárias
  • O método exato (B&B do HiGHS) resolve bem grafos pequenos
  • A dificuldade cresce exponencialmente: de 0,08 s para 300 s
  • O gargalo é provar a otimalidade, não achar a solução
  • Melhorias: formulações mais fortes (representantes, geração de colunas)
